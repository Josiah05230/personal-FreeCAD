# CLAUDE.md - GWT-CAD

Fusion-360-style CAD application: FreeCAD 1.1.1 runs headless as the geometry/parametric kernel, the whole front end (Electron + React + three.js) is custom. Scope: part modelling, assemblies, drawings, sheet metal, non-planar body splitting. Linux and Windows are supported targets (Mac packaging not scoped: needs signing/notarization and a Mac to build). No visible "workbench" concept. Viewport feel is a hard requirement. Rationale for own-shell + headless-kernel: `docs/decisions.md` (D-0000..D-0004).

This repo is PUBLIC (github.com/Josiah05230/personal-FreeCAD, branch `main`). Keep committed docs, comments and this file technical only: no credentials, internal hostnames/IPs, account or customer data, pricing.

## Where things are documented

- `docs/status.md` - current state and full capability list. `docs/FEEDBACK.md` - live-test issue queue. `docs/fusion-parity.md` - Fusion 360 command-by-command parity list (check it before adding or altering a feature; the goal is F360-matching behaviour, not our own interpretation). `docs/packaging.md`, `docs/first-time-setup.md`, `docs/decisions.md`, `docs/roadmap.md`.
- Per-change detail lives in git history (descriptive commits). This file is orientation and gotchas only.

## Layout

- `app/src/renderer` - React 18 (StrictMode) + three.js. `App.tsx` is the hub (~2700 lines): selection, op dialogs, live preview, timeline wiring, the `window.__gwtcad` test bridge. `viewport/` = scene (`sceneBuilder.syncScene` incremental reconcile, `Picker`, `CadControls` constrained-turntable orbit). `ui/` = ribbon / Timeline / Browser / OperationDialog. `cmdQueue.ts` serialises every model mutation. `trace.ts` = action/RPC log. `rpc.ts` = typed wrappers (`api` vs `apiQuiet`). `commands.ts` = ribbon/hotkey commands.
- `app/src/main` - Electron main. `sidecar.ts` spawns + auto-respawns the Python sidecar (bundled, then config, then PATH); `index.ts` has the `--e2e <scenario>` harness.
- `sidecar/` - runs under FreeCAD's own interpreter. `server.py` (threaded HTTP + ONE engine worker thread; all FreeCAD calls serialised on it), `gwtcad/registry.py` (`@method`, `dispatch`, `_NO_TXN` set, `_trace`), `gwtcad/methods.py` (all RPCs; feature modules `primitives`, `xform`, `meshtools`, `materials`, `appearance`, `tables`, `pdscale`, `pdsplitface` are imported by a guarded loop at the BOTTOM of `methods.py` and use a lazy `from . import methods as _m` inside each RPC to dodge the circular import), `gwtcad/build.py` (shared geometry helpers: `finalize_or_rollback`, `reusable_profile`, `dress_up`, `pad`/`pocket`, `scratch_body_from_shape`), `gwtcad/session.py` (one-doc state, markers, params, feature exprs), `gwtcad/expr.py` (unit expressions), `drawing.py`, `tessellate.py`, `mesh_pool`, `mesh_disk.py`.
- `test/e2e/` (Electron-driven scenarios + fuzzer), `test/unit/` (pure-node TS tests), `scripts/` (dev/build/package), `config.example.json` -> `config.local.json` (git-ignored; set the `freecadcmd` path).

## Run / build / test

- Setup: `cp config.example.json config.local.json` (edit `freecadcmd`), `cd app && npm install`. FreeCAD 1.1.x AppImage extracted or a system install providing `freecadcmd`; Node 18+.
- Dev: `scripts/dev.sh` (full app; clears `ELECTRON_RUN_AS_NODE`), `scripts/sidecar-dev.sh` (sidecar only, poke with curl). Typecheck: `cd app && npm run typecheck`.
- E2E: `bash test/e2e/run.sh [scenario.js ...]` (builds, then launches the real app per scenario and drives it through `window.__gwtcad`). `fuzz.js` + `fuzz-loop.sh` = always-on random walker. `fusion_features.js` needs `E2E_TIMEOUT=900`. Unit: `bash test/unit/run.sh [file]`.
- Package/install: `scripts/package.sh linux|appimage|deb|win|dir` (bundles headless FreeCAD into `app/resources/freecad/`, trims GUI-only weight 3.1GB->2.3GB with a guarded headless-import check that rebuilds untrimmed on failure; `GWTCAD_NO_TRIM=1` skips; Windows from Linux needs `wine`). `scripts/build-install.sh [--deb|--appimage|--dir] [--e2e] [--no-launch]` = typecheck -> optional E2E -> package -> smoke-test the packaged binary boots its bundled FreeCAD -> install (.deb via `sudo apt install`, AppImage to `~/.local/bin`) -> launch. Config: `app/electron-builder.yml`.
- Trace: on by default, every action / cmd-queue transition / RPC (both sides, paired, ms) goes to `/tmp/gwtcad-run.log`. Silence with `localStorage gwtcad.trace=0` or `GWTCAD_TRACE=0`.

## Rules

- **Everything stays PartDesign** (Body > Sketch > Pad/Pocket/Fillet/...), never raw Part booleans. Why: the timeline and `.FCStd` round-trip (files must open and stay editable in stock FreeCAD) only mean something with a real feature tree. A vocabulary layer means the UI never says "Pad".
- **Verify with E2E, and drive real input where the bug class needs it.** Why: most escaped bugs came from scenarios that skipped the layer in question (sketcher scenarios that went straight to `sketch.finish`; op scenarios that never fired the live preview; `G.pick()` bypassing the real raycast/keydown handlers). Use `__gwtcad.pick(sel, additive)` (routes through real `onSelect`; the `select` bridge is a raw setter), the sketch test hooks on `window.__gwtcad.sketch`, `interactive_preview.js` for live-preview ops, `real_input.js` for synthetic PointerEvent/KeyboardEvent.
- **Always unset `ELECTRON_RUN_AS_NODE` before running Electron or the packaged binary.** Why: otherwise Electron starts as plain node and exits silently.
- **Hotkeys follow Fusion 360's actual defaults** (only ~20 commands have one): E/F/Q/H/M/J/I etc. in `commands.ts`; Measure is `I`, Move is `M`.
- **Commit and push after every meaningful change.** Why: work not in git has been lost before.
- No em dashes or en dashes in docs, code or commit messages (plain hyphens).

## Conventions and subsystem notes

- **Live preview**: `feature.previewUpdate(id, props)` (in `_NO_TXN`) sets props in place, one recompute, returns just the affected body's mesh keyed by `body.Name`. `feature.previewSetBase(id, subs[, points])` does the same for a dress-up whose edge/face set changed. Client `livePreviewRef` state machine in `App.tsx`; `previewSig` hashes kind + refs + op/mode/cut/axis. Dress-up dialogs: plain click REPLACES the edge/face set, Ctrl/Shift/Cmd-click adds. Dress-up selections dedupe by the 3D click point (`samePick`), and the sidecar resolves refs by that world point first (`_resolve_dressup_subs` -> `_nearest_edge_on`/`_nearest_face_on`); names are the last resort because a live-preview feature renumbers Edge*/Face*. Fillet/chamfer/shell/draft always rebuild from the full current selection on commit. While such a dialog is open, referenced edges/faces render as an amber "ghost" overlay you can click to deselect (`baseRefs` from the sidecar, `dressUpGhost` state).
- **Editable features**: `feature.get` / `feature.update` / `feature.editPreview` (subset recompute). `App.editFeature` rolls the marker to the feature, seeds selection from its refs, opens the dialog with `initialValues`.
- **Bad builds roll back surgically**: `build.finalize_or_rollback(..., check_made=True)` removes only the new feature, restores the tip, fails a feature that produced no shape (extrude / revolve / update / mirror / pattern).
- **Resolve refs BEFORE `body.newObject`**: Transformed/Revolution features auto-advance `body.Tip` to themselves, so an axis/plane ref resolved afterwards goes through the half-built feature -> "The graph must be a DAG" -> null shape -> silent no-op.
- **`PartDesign::Body.Tip.Shape` excludes the body's own Placement; `Body.Shape` includes it.** `_resolve_ref`'s face/edge/vertex branch resolves through `Tip` because PartDesign features may only reference siblings in their OWN body's Group (referencing the Body trips "out of the allowed scope"/DAG errors). Consequence: a cross-body face/edge ref on a body moved via Move/Copy resolves its PRE-move position unless the consumer composes the owning body's Placement back in. `body_split` does; `body.align`, primitive `planeRef`, pipe `pathRefs` do not (latent risk).
- **A sketch is never "consumed"**: `build.reusable_profile` hands later features a hidden `gwtRefCopy`-tagged copy, filtered from `tree.get`/`scene.get`, GC'd by `build.gc_profile_copies`.
- **Mirror / Pattern scope**: `_transform_originals(body, scope, refs)`: `body` (default whole solid-feature chain), `features` (Timeline chip selection via `onSelectFeatures` -> `App.timelineSel`), `faces` (features owning picked faces, `_features_for_faces`). Operation join/cut/intersect/newbody via `_finish_transform` + `_apply_result_boolean`; Sweep/Loft/Revolve share it. Mirrored/LinearPattern/PolarPattern are editable via `_TYPE_KIND`.
- **Extrude**: "Two Sides" cannot use `Pad.Type="TwoLengths"` (null shape in this FreeCAD 1.1.1 build); built as two sequential additive pads in opposite directions (join only). "All" = `Type="ThroughAll"` (Cut+Blind only). Intersect = scratch Body + `PartDesign::Boolean` Type=Common; consumed tool bodies filtered by `_boolean_consumed_bodies`, helpers by `_xform_helper_features`. Cut auto-flips `Reversed` if the first pass removes nothing.
- **Scripted PartDesign features** (Scale `pdscale.py`, Split Face `pdsplitface.py`): `body.newObject("PartDesign::FeaturePython", ...)` wires `BaseFeature` and advances Tip like a native feature; proxy `execute` re-derives from the ORIGINAL base shape (never compounds) and survives save/reopen. `methods._scripted_kind(o)` disambiguates the shared TypeId by checking own properties (`Uniform`, `PlaneSupport`): extend that for new ones. Scale only takes this path for `PartDesign::Body`; bare `Part::Feature`/meshes use a baked shape. If using `generalFuse`, keep only `compound.Solids` (the compound includes the tool plane's leftover slice, which silently explodes the bbox while `isValid()` stays True).
- **Datum tools**: `_attach_datum` picks an Attacher MapMode from the ref set. `MidPoint` and `IntersectionPoint` are NOT implemented in FreeCAD 1.1.1 (fall back to a computed `Deactivated` placement).
- **Primitives** (`primitive.box/cylinder/sphere/torus/coil/pipe`) are Additive*/Subtractive* PartDesign; placement via `AttachmentSupport` + `MapMode="FlatFace"` from `planeRef` (box/cylinder/sphere/torus only; coil/pipe origin-only).
- **Sketcher** (`SketchController.ts`, ~3100 lines): points are `PtRef {e, pt:1|2|3}` (start/end/centre; `e:-1` = sketch origin, ref `{geo:-1,pt:1}`); projected geometry is real FreeCAD external geometry (`addExternal` rejects the Body, use `body.Tip.Name`), kept in `SketchController.projected` (selection idx `>= PROJ_BASE`). Constraint reopen must treat FreeCAD's real unset sentinel as -2000 (not `<= -3`). Radius vs Diameter are distinct end to end (prompt accepts `d20`/`Ø20`). Tangent: endpoint Tangent (`pt` on both refs) for arc endpoints, `PointOnObject` + edge Tangent for full circles. Run snap-based auto-constraints before `anchorToAxes`. `SketchController` and `Picker` take a `() => camera` getter, never a captured camera (orthographic is the default view and a different camera object). Center Rectangle: the crossing of the two welded construction diagonals is the centre (no extra symmetric constraint; it over-constrains). `sketch.reopen` reads construction via `sk.getConstruction(gid)`.
- **View/camera**: `CadControls` holds `persp` (pose source of truth) + `ortho` glued via `syncOrtho()`; call `syncOrtho()` at every direct pose mutation (`frame`, `applyOrbit`, pan, wheel), not only in the rAF loop (rAF stalls in the E2E window make Home/zoom look dead). Default orthographic, persisted in `localStorage gwtcad.projection` (E2E normalises it first), F5 toggles. Framing boxes ignore datums (`SceneNode.frame`). `Picker` edge-vs-face tie-break: an edge wins only if the click is near it on screen, checked across all hits.
- **Sections** are saved tree objects (`session._sections`, `section.*` RPCs in `_NO_TXN`, persisted in the `.gwtcad` companion). **Appearances** (`appearance.py`, `appearance.ts`): view layer only, applied instantly client-side AND queued to the engine, persisted in the `.gwtcad` companion; presets overrule only the keys they define; `tessellate.py` classifies edges sharp/tangent/free (`TANGENT_ANGLE_DEG=12`). **Materials** (`materials.py`): real FreeCAD `Material` via `ShapeMaterial`, custom presets in `~/.gwtcad/materials.json`, extras in `session.material_extra`; a custom material with its base's UUID reverts to stock look after a real close+reopen in plain FreeCAD (GWT-CAD replays via `reapply_custom_materials()`); `getPhysicalValue` returns a non-JSON `Base.Quantity`. Mass properties: many presets carry no Density; `PrincipalProperties["SymmetryPoint"]` can be a bool.
- **Mesh**: `mesh.toSolid` routes through `build.scratch_body_from_shape` so the result is a sketchable `PartDesign::Body`. "flats" mode recognises planar regions (`getPlanarSegments` + `wireFromMesh`) and sews them with leftover facets; round/cylinder recognition is not implemented (FreeCAD's `getSegmentsByCurvature` found nothing reliable). Import is capped (default 200k triangles, `SettingsPanel.tsx`/`meshPrefs.ts`).
- **Server hardening**: `server.py`'s `_json` wraps `json.dumps` so a non-serialisable result returns a JSON-RPC error instead of dropping the connection (client otherwise sees "fetch failed").
- **Drawings** are native TechDraw/Spreadsheet objects inside the `.FCStd` (no shadow state): multi-page, section/detail/broken views, `DrawViewDimension`, notes with leaders, parametric BOM + savable table templates (`~/.gwtcad/table_templates.json`, `tables.py`). `drawing.pageContents` rehydrates a reopened page. FreeCAD 1.1.1 traps: (1) a `DrawViewDetail` background worker segfaults a headless close/reopen unless you `doc.recompute()` + sleep 0.3s first (`session._settle_detail_views`); (2) `view.projectPoint()` is uncentered vs `getVisibleEdges()`: correct by diffing bbox min corners of projected vertices (`drawing._project_offset`), NOT `getGeometricCenter()` or edge-index matching; (3) removing a DrawPage that still holds a projection group segfaults (delete children first); (4) `App.openDocument` on an already-open file returns THAT doc (closing it kills the session doc). Generated views must be coarse from the first compute (`coarse=True`): exact HLR on spring/thread models takes minutes per view. `hlr.py` toggles face search only while computing (the pref is saved into the shared FreeCAD user.cfg). Never change `_shape_key`'s format (area is in every saved view-cache key; changing it forces HLR recompute of all saved drawings). Rescale = scale cached polylines, never recompute.
- **Perf architecture (keep)**: `tessellate.py` meshes a whole shape in ONE MeshPart call (`Segments=True` -> per-face groups), un-welds + orients in numpy, classifies edges from shared normals. Shapes with 250+ faces (or past ~600-face per-call budget) get a draft mesh plus a full mesh from `mesh_pool` (persistent freecadcmd workers); the shell polls `scene.refined`; `scene.get` absorbs refines first and the shell keeps refined meshes by id+sig. `_shape_sig` = counts + vertex checksum (no Area: 1.4s uncached). Body edges = one LineSegments per body. RPC trace `clip()` must summarise arrays. Never mesh in an engine-side thread (OCCT holds the GIL). Persistent caches: `mesh_disk.py` (`~/.gwtcad/meshcache`, 2GB LRU), `drawing-areas.marshal`.
- **Document/PDM model**: parts are FLAT: `<project>/<type>/<pn>.FCStd` (+ `.stp`, `_supplier_meta.json`, `<pn>.FCStd.gwtcad.json` companion). Locks are per file: `.<file>.gwtcad-lock.json`. Saving an active/discontinued revision forces the next revision (reason required); in-work saves in place; a superseded revision refuses to save. Going active runs `drawing.refreshForRevision` (generated drawings stamped `_gwt_autogen` are rebuilt if untouched). History panel is per-file (`git.fileLog --follow`); auto-commits use `git.commitFile` (scoped), never commit-all in a monorepo. Registry undo = `pn.registryRestore` (a new commit, never a rewind). Data Panel shows only usable types (`app/src/shared/fileTypes.ts`); outside files go through `pn.copyIn`.
- **Auto drawings**: any part file with geometry but no drawing gets one (`supplier_models.generate_part_drawing`), from the promotion gate and a detached startup job (`gwtcad/draw_missing.py`, log `~/.gwtcad/draw-missing.log`, which also records failed PDF uploads).
- **Drawing QA gate**: `firebase_storage.upload_file` runs `drawqa.gate` on every `cad-exports/<PN>/<PN>.pdf` before uploading (title block fields filled in and matching the registry, mfg PN note on purchased parts, registry BOM lines present on assembly drawings, no placeholders/dashes, nothing off-page or blank). A refusal raises with every problem; callers report it (`pdfError`, `export_promote` errors). No override by design.
- **App-wide undo**: `renderer/appHistory.ts`; Data Panel delete = `main/softDelete.ts` holding area (`~/.gwtcad/deleted`). Any new user action that changes disk/config must push an appHistory action (call `syncDocSteps()` first if the flow also touched the doc).
- **Multi-window + live reload**: each window is its own app process + sidecar (`--open <file>`); `main/fileWatch.ts` polls the open doc + linked parts, renderer reloads (or asks if dirty). Own saves are rebased in main's `cad:rpc` (`WRITES_FILES`). Leaving a tab always saves if allowed (`leaveCurrentDoc`).

## Gotchas

- **Installed app vs source sidecar**: an installed build (e.g. /opt/GWT-CAD from a .deb) runs its own bundled sidecar code. Bugs fixed in source stay live in the installed app until reinstalled (`scripts/build-install.sh --deb`, needs sudo). Concrete case: an installed build had a drawing-export bug (a dimension with no tolerance: "object of type 'NoneType' has no len()", fixed in b970bc1). Its background draw-missing worker then built the drawing inside the FCStd but the PDF upload failed silently (failure logging added in c9d62b6, also only live after a reinstall). Scripts that run against the SOURCE sidecar (`GWT-CAD/sidecar`) are unaffected. After any drawing-related change, verify the generated PDF actually arrived at its destination rather than trusting the worker.
- **pull --autostash trap**: the app's registry sync and auto-generated drawing commits run `git pull --rebase --autostash` in the company CAD repos. If a user or script has UNCOMMITTED edits in that repo at that moment, they can end up in `git stash` (or dangling "autostash" commits) while the app's rebuilt `.FCStd` files still get committed, leaving a build script older than the part it builds. Before rebuilding a part from a script: `git stash list`, compare the existing `.FCStd` feature list with what the script makes, and commit script edits BEFORE building. Recover with `git diff stash^ stash -- <files> | git apply --3way`.
- **Drawing view cache versions**: views load their hidden-line geometry from `GwtDrawingCache.json` inside the `.FCStd`. A file whose cache version the loader can't read recomputes HLR on its next export (CMP0020: about an hour; with the v2 converter, 9 s). Never bump `_CACHE_VERSION` without adding a converter in `load_view_cache` (see `_cache_v2_to_v3`, checked pixel-identical against a recompute).
- `freecadcmd` swallows CLI flags: pass host/port via `GWTCAD_HOST`/`GWTCAD_PORT`.
- Each E2E / script run spawns a `freecadcmd server.py`; orphans pile up and OOM the live sidecar. Kill `-f 'GWT-CAD/sidecar/server.py'` and `-f 'GWT-CAD/app/node_modules/electron'` before relaunching. A stuck rootless-`:1` GPU can wedge new electrons (restart the display/IDE). `pkill` often exits 144 and half-completes; prefer an explicit PID loop. `ps`/`pgrep` may see nothing inside the Claude Code sandbox: use `dangerouslyDisableSandbox`.
- Foreground `sleep` is blocked in the Claude Code Bash tool: use `run_in_background` or a Monitor until-loop.
- GUI launch that survives across turns: Bash `run_in_background` + `dangerouslyDisableSandbox`, run `electron-vite dev` directly (NOT through a wrapper script; it gets reaped) with `unset ELECTRON_RUN_AS_NODE; export DISPLAY=:1 ELECTRON_DISABLE_SANDBOX=1`, `--no-sandbox`, output appended to `/tmp/gwtcad-run.log`. Renderer hot-reloads; main/preload/sidecar changes need a full relaunch (the sidecar auto-respawns into new code when killed).
- E2E: re-read `window.__gwtcad` each time (bridge recreated per render); context menus close on window blur (pick items synchronously); `git_ops`/`git_pull` leave `/tmp/gwtcad_git_*` dirs that break the next run (move aside); `answerNextPrompt` bridge hook answers `promptForm`. Known failing in their own setup: `monkey.js` check 6 (refresh race after `session.reset`; `fuzz.js` covers it), `asm_pin.js`.
- E2E / `--drive` / `--shot` windows render off-screen and are never shown (`HIDDEN` in `main/index.ts`; `GWTCAD_SHOW=1` to watch, `GWTCAD_HIDDEN=1` for any other launch, e.g. the packaged smoke test). Don't point a scenario at files in the real company repos: opening one takes a lock (a commit + push) and its background pull/lock work runs against the shared repo. Copy files to a scratch dir, or build a scratch bare remote + clone for git behaviour.
- `FIRST RUN` wizard (`ui/FirstRun.tsx`, localStorage `gwtcad.firstRun.done`) is suppressed by `window.cad.isE2E`.
- Live GUI verification: drive the packaged/dev app with an ad hoc Playwright script built fresh in a scratch dir (not committed).
